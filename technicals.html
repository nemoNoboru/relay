What a node is

Relay is one Go binary. A node is one copy of it running on a computer that someone in the group keeps — an old laptop, a small server, a Raspberry Pi.

The node serves the group's posts as ordinary static web pages under one hostname:

https://relay.example.org/<node>/<post>/

There is no build step, no database to install, and no cloud account. Everything the node knows lives in one data directory. Back that directory up and you have backed up the node.

A node is meant for a group of roughly 4 to 29 people, not for the public internet. People join by invitation link. There is no sign-up page.

A post is a small website

A post is a folder of files. The node serves it as it is:

<data>/sites/sunday-walk/
  index.html
  assets/photo-1.jpg
  assets/photo-2.jpg

The social layer adds an index beside it — who published it, when, with which template — but the content never depends on that index. You can copy the folder anywhere and open it without Relay.

Uploading is one POST of a tar archive, authenticated with an invitation key. The new version replaces the old one all at once. The previous ten versions are kept so a mistake can be undone.

Invitations, not accounts

There are no accounts, passwords, or email addresses. An invitation link carries a key. Opening it makes the browser a member of that node. That is the whole account system.

host ── invite ──► Alice ── invite ──► Bob
                     └──── invite ──► Dana

revoke Alice  →  Alice, Bob, and Dana lose their keys

A member can invite people they vouch for. The host can revoke a whole branch at once. There is no password to recover: if a link is lost, the host rotates the key and sends a new one.

The social layer we are building

The hosting core, the member welcome, and the post index are done. The pivot adds the place around it:

  • Welcome — open an invitation once, stay signed in, set a display name and a short bio. Live.
  • Home feed — every member's posts, newest first, loaded as you scroll, with comments and a comment box under each post. No ranking, no likes, no counts. Live.
  • Profiles — one page per member with everything they have shared, also an infinite scroll with inline comments. Live.
  • Post pages — the page, its author, its date, and a place for comments. Live.
  • Comments — replies under a post, visible to members, with host deletion. Static posts are sandboxed, so comments live on the trusted post page rather than inside the post itself. Live.
  • Templates — Note, Link, Gallery, Article, Songs, Videos, Images Carousel, Jet Set Radio, and Longform forms, with live previews. Members can install a template tar from the publish page, so the set is not fixed. Template code runs in the browser; the node only accepts the finished files. Live.

The feed is deliberately chronological. A node is small enough that the group can see what everyone posted without an algorithm deciding for them.

Keep a node

Every node needs a name (the first path segment of its posts) and a data directory. On first start the admin password is relay; the console asks you to change it before you do anything else.

Binary

Linux or macOS, amd64 or arm64:

curl --proto '=https' --tlsv1.2 -sSfL \
  https://raw.githubusercontent.com/nemoNoboru/relay/main/install.sh | sh

relay node --name my-group --data /var/lib/relay --listen :8080

Open http://localhost:8080/_relay/admin.html, sign in with relay, choose a new password, and create the first invitation.

Docker

The image runs unprivileged and keeps all state in /data. Flags after the image name are passed to relay node:

docker run -d --name relay --restart unless-stopped \
  -p 8080:8080 -v relay-data:/data \
  ghcr.io/nemonoboru/relay:latest --name my-group

The admin password is written to /data/admin-token; read it with docker logs relay on first start.

Kubernetes

One command installs a relay namespace, a single-replica StatefulSet with a persistent volume, and a Service:

kubectl apply -f https://raw.githubusercontent.com/nemoNoboru/relay/main/deploy/kubernetes.yaml
kubectl exec -n relay relay-0 -- cat /data/admin-token

The node serves HTTP on :8080 with probes on /healthz. For TLS, put your hostname in deploy/ingress.yaml and apply it. One host and one certificate cover every post.

HTTPS

Pass --tls-cert and --tls-key to serve HTTPS directly, or put Caddy or Nginx in front. When testing with a self-signed certificate, add --insecure to relay deploy and relay rollback.

Backups and limits

The data directory is the backup unit:

<data>/
  admin-token
  deploy-keys.json
  sites/
    <site>/
    .versions/<site>/<id>/
  • Stop the node, copy the directory, start it again. Or copy it while running for a best-effort snapshot; stop it for a guaranteed one.
  • Upgrading an old node? relay index --data <dir> adds existing sites to the feed.
  • Hosts manage extra templates with relay template list|install|remove.
  • Defaults: 256 MiB and 65,536 files per post; the last 10 versions are kept.
  • Invitation keys can be revoked or rotated from the host console.
  • A node is not a public host. Keep it for people you know.
