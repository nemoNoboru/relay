Upload a static site

One request and the site is live at /<node>/<site>/: a tar archive of the folder's contents, sent with a deploy key — a per-user credential the node operator creates on the operator console. Uploads atomically replace whatever was there before.

Example

tar -C ./dist -cf site.tar .
curl -X POST \
  -H "Authorization: Bearer $RELAY_DEPLOY_TOKEN" \
  -H "Content-Type: application/x-tar" \
  --data-binary @site.tar \
  "https://relay.example.org/_relay/v1/sites/docs/deploy"

The response names where the site is live:

{"site":"docs","files":3,"bytes":5120,"url":"/mynode/docs/"}

{site} is a lowercase name: letters, digits, and interior hyphens, 1–63 characters. Keep asset paths relative so the site works at any path depth.

Credentials

Upload with the deploy key's token as a bearer token — never in a URL, never committed, never logged. The admin token is separate and operator-only: it unlocks the console, not uploads.

Archive rules

  • Relative paths only — no .., no absolute paths, no symlinks or hard links.
  • Regular files and directories only.
  • At most 65536 files and 256 MiB per upload.
  • Every upload is a full replacement — send the whole site each time.

Errors

codeHTTPMeaning
bad_token401missing or wrong token
bad_name400the site path segment is invalid
bad_archive400not a tar, or an entry breaks the rules
too_large413archive over the size cap

Rollback

Deploys keep the last 10 versions, and the live site is snapshotted first — roll back from the console or with relay rollback --origin … --site …. The relay binary also uploads: relay deploy --origin … --site … ./dist.
