Upload a site

Send a tar archive of your folder with your deploy key, and the site goes live at /<node>/<site>/. You get a deploy key from whoever runs this node; if that's you, issue one in the operator console.

Upload

tar -C ./dist -cf site.tar .
curl -X POST \
  -H "Authorization: Bearer $RELAY_DEPLOY_TOKEN" \
  -H "Content-Type: application/x-tar" \
  --data-binary @site.tar \
  "$RELAY_ORIGIN/_relay/v1/sites/mysite/deploy"

The response tells you where the site is live:

{"site":"mysite","files":3,"bytes":5120,"url":"/mynode/mysite/"}

Site names use lowercase letters, digits, and hyphens in the middle, up to 63 characters. Keep asset paths relative so the site works under its path. If you have the relay binary, the same upload is one line: relay deploy --origin $RELAY_ORIGIN --site mysite ./dist.

Archive rules

  • Archive what's inside the folder (tar -C ./dist … .), not the folder itself.
  • Relative paths only. No .., no absolute paths, no symlinks or hard links.
  • Up to 65,536 files and 256 MiB per upload.
  • Each upload replaces the whole site, so include every file each time.

Errors

Rollback

The node keeps the last 10 versions of every site. The operator rolls back with the admin token: relay rollback --origin $RELAY_ORIGIN --site mysite. Rolling back saves the current version first, so nothing is lost.

Keep your key secret

Send it only in the Authorization header. Never put it in a URL, a commit, or a log. If it leaks, ask the operator to rotate it. The admin token is separate and only for the operator. You never need it to upload.

Deploy with an agent

Give your agent the node's address, your deploy key, and the deploy skill. It covers the same steps in a form agents can follow.
