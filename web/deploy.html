Upload a static site

Relay serves a site folder at /<node>/<site>/. To put a site there, upload a tar archive of the folder to the node. One request, and the site is live — atomically replacing whatever was there before.

The endpoint

POST /_relay/v1/sites/{site}/deploy
Authorization: Bearer {token}
Content-Type: application/x-tar

The body is the raw tar bytes of the site folder's contents (not the folder itself). {site} is a lowercase name: letters, digits, and interior hyphens, 1–63 characters.

Example

tar -C ./site-folder -cf site.tar .
curl -X POST \
  -H "Authorization: Bearer $RELAY_DEPLOY_TOKEN" \
  -H "Content-Type: application/x-tar" \
  --data-binary @site.tar \
  "https://relay.example.org/_relay/v1/sites/docs/deploy"

The response names where the site is live:

{"site":"docs","files":3,"bytes":5120,"url":"/mynode/docs/"}

The deploy token

The deploy token is the credential that authorizes uploads. The node keeps it in <data>/upload-token (mode 0600) and prints it once on first run — or the operator sets it with relay node --upload-token. Hand it to whoever deploys as a bearer token: never in a URL, never committed, never logged.

The key

Relay's permanent identity is an Ed25519 key — the deed to a name. relay key new generates one. For this MVP the token is what authorizes uploads; keys and signed deploys arrive with the control API. See docs/keys.md in the source.

Archive rules

  • Relative paths only — no .., no absolute paths, no symlinks or hard links.
  • Regular files and directories only.
  • At most 65536 files and 256 MiB per upload.
  • Every upload is a full replacement — send the whole site each time.
