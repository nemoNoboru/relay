Deploy

Live in three steps

All you need is a deploy key from this node. Your site goes live at /<node>/<site>/ the moment the upload finishes.

01

Get a key

Ask whoever runs this node for a deploy key. If it's your node, make one yourself in the operator console. You won't need an account.

Operator console
One key per person
02

Pack the folder

Archive what's inside the folder, not the folder itself. Keep links relative.

tar -C ./dist -cf site.tar .
Up to 256 MiB · 65,536 files
03

Upload

curl -X POST \
  -H "Authorization: Bearer $RELAY_DEPLOY_TOKEN" \
  -H "Content-Type: application/x-tar" \
  --data-binary @site.tar \
  "$RELAY_ORIGIN/_relay/v1/sites/mysite/deploy"

$RELAY_ORIGIN is this node's address · $RELAY_DEPLOY_TOKEN is your key · mysite is your site's name

Full guide Agent skill
Each upload replaces the whole site · last 10 kept

Have the relay binary? It's one line: relay deploy --origin $RELAY_ORIGIN --site mysite ./dist

Run a node

Host your own

A node is one binary and one data directory. It serves sites, hands out deploy keys, and keeps every byte on a disk you control.

01

Binary

curl --proto '=https' --tlsv1.2 -sSfL \
  https://raw.githubusercontent.com/nemoNoboru/relay/main/install.sh | sh

relay node --name mynode --data /var/lib/relay --listen :8080
Linux · macOS · amd64 · arm64
02

Docker

docker run -d -p 8080:8080 -v relay-data:/data \
  ghcr.io/nemonoboru/relay:latest --name mynode

Prefer Kubernetes? It's a single kubectl apply.

Docker Kubernetes
Runs unprivileged · state in /data

The node prints an admin token on first start. Use it to sign in at /_relay/admin.html and issue keys.
